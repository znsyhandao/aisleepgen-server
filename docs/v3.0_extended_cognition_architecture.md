# AISleepGen v3.0 架构设计：延展认知（Extended Cognition）

> 源于认知科学史对AI的映射——具身认知之后的下一个大突破是延展心智。
> 智能不局限于服务器+小程序的封闭系统，而是延伸到时间、环境、社会关系、用户的自我觉察中。
> 从"AI管理用户睡眠" → "AI帮助用户发展自己的睡眠觉察能力"。

## 2. 范式跃迁：延展认知

### 核心思想

认知科学中"延展心智"（Clark & Chalmers, 1998）的核心主张是：
**认知过程不限于大脑内部，而是延伸到环境和工具中。**

类比到AISleepGen：
**用户的睡眠认知不限于"打开小程序→填问卷→看分析"这几分钟，而是延伸到了入睡前的环境、夜间的体动模式、第二天醒来后的感受。**

**v3.0 的目标：** 从"睡眠分析工具" → **"睡眠认知伴侣"**

| 维度 | v2.x (分析工具) | v3.0 (认知伴侣) |
|------|----------------|----------------|
| **时间** | 用户打开小程序才启动认知 | 24/7持续认知，节律感知贯穿全天 |
| **空间** | 局限在小程序内 | 延伸到环境线索推断 |
| **社会性** | 用户是孤立的个体 | 感知关系场景（独居/同居/有娃） |
| **互动模式** | AI提问→用户回答 | 双向觉察：AI帮用户发展自我感知 |
| **成功标准** | 单次评分准确 | 用户睡眠觉察能力提升 |

## 3. 四个新模块的详细设计

### 3.1 昼夜节律相位模型 `circadian_phase_model.py`

**评估：适合纯规则引擎。** 节律相位拟合本质上是数学问题（余弦函数拟合），不需要大模型。关键是从无到有。

**问题：** 目前预测今晚评分只基于历史评分做线性外推，完全没有生物节律的概念。

**解决方案：** 为每个用户建立一个个性化的24小时睡眠节律相位模型。

```python
class CircadianPhaseModel:
    """
    个人昼夜节律相位模型

    核心变量：
      - acrophase: 节律峰值相位（常规是下午~傍晚，失眠患者可能偏移）
      - amplitude: 节律振幅（节律越强，到点越容易困）
      - phase_angle: 相位角（就寝时间相对于核心体温节律的位置）
      - drift_rate: 相位漂移率（每天推迟/提前多少分钟）

    输入更新：
      - 每次问卷中的上床时间、入睡时长
      - 聊天中出现的时间线索（"我12点才睡"）
      - 陪伴模式的入睡检测

    输出：
      - predicted_drowsiness(hour): 某时刻的犯困概率
      - optimal_bedtime: 基于节律的最佳就寝窗口
      - phase_shift_warning: 相位偏移警告（连续N天推迟>阈值）
    """
```

**关键算法：**
- 用小样本的入睡时间 + 起床时间拟合 simple cosine model
- 相位角 = 上床时间 - 节律峰值相位（健康人~6h，失眠患者可能>8h）
- 漂移检测：连续N天平均入睡时间推移超过阈值 → 标记 circadian_risk
- **v3.0 核心新增：** 不仅用问卷，还从对话时间推断

**数据原理：**
```
if user chats at 2am on 3 consecutive days:
    → 触发 phase_shift_warning
    → 稳态回路写入信号 circadian_drift_severe
    → 干预回路选择"提前上床"建议 + 附加"你的入睡时间在持续后移"
```

**与现有系统的接口：**
- 通过 `report_body_event(openid, 'circadian_update', {...})` 写入稳态回路
- 稳态回路新增信号 `SIG_CIRCADIAN_PHASE` 和 `SIG_CIRCADIAN_DRIFT`
- 预测引擎 `predict_tonight()` 增强：加入节律相位作为输入特征

### 3.2 社会情境感知 `social_context.py`

**评估：不适合纯规则引擎。** 社会情境需要语义级理解。采用**异步管道 + DeepSeek**：后台分析最近N次对话，提取结构化情境信息，缓存供后续使用。规则引擎做关键词初筛（快速给出低置信度推断），大模型做语义精校。

**问题：** 独居用户的失眠干预策略完全不同。同居用户需要考虑伴侣/室友/孩子的干扰。

**解决方案：** 从对话中被动推断社会情境，不需要用户主动填写。

```python
class SocialContext:
    """
    社会情境推断

    采用两级推断：
      Level 1 (规则引擎, <1ms): 关键词匹配初筛
      Level 2 (非阻塞LLM, 后台): 语义精校 + 置信度提升

    从聊天消息中提取的社会情境维度：
      - living_arrangement: 'alone' | 'with_partner' | 'with_family' | 'with_roommate'
      - social_interference: ['snoring', 'baby_crying', 'partner_shift_work', ...]
      - social_support: 'has_support' | 'isolated'
      - inferred_from: ['keyword_match', 'llm_analysis', 'pending_confirmation']

    回退策略：
      - LLM不可用 → 仅使用Level 1结果，标注低置信度
      - 置信度<0.3 → 不使用该信号（不如没有）
      - 多次不一致 → 降低该用户的情境推断权重
    """
```

**关键能力：**
- `infer_living_arrangement(message)` → 关键词初筛
- `async_analyze_social_context(openid, recent_chats)` → 后台LLM分析（写入稳态回路信号）
- `detect_social_disturbance(profile)` → 从累积信号中检测社会性睡眠扰动
- `personalize_strategy(ctx)` → 根据社会情境调整干预策略
  - 独居 → 推荐白噪音/宠物/夜灯
  - 有伴侣 → 推荐分被/耳塞/协商作息
  - 有娃 → 推荐分段睡眠/轮流值班策略

**与异步管道的集成：** 社会情境分析复用 `async_pipeline.py` 的后台线程机制，不阻塞主请求。结果缓存4h。

### 3.3 环境线索推断 `environment_inference.py`

**评估：不适合纯规则引擎**（理由同社会情境）。采用**两级策略**：规则初筛 + 非阻塞LLM语义精校。时间模式分析（"深夜还在聊"）可用规则，具体活动推断（"喝了咖啡" vs "在咖啡馆"）需要上下文理解。

**问题：** 没有传感器，但用户的对话本身隐含了大量环境信息。

**解决方案：** 从时间戳+消息内容+长度推算出无法直接感知的环境状态。

```python
class EnvironmentInference:
    """
    从对话模式推断环境状态（无传感器条件下的被动感知）

    两级推断策略：
      Level 1 (规则引擎, <1ms):
        - 时间槽检测：chat_timestamp → 时段（睡前/深夜/凌晨/白天）
        - 简短消息检测：len(message) < 10字+深夜 → 可能半睡半醒
        - 关键词快速命中：'咖啡'/'加班'/'卧室'/'床上'
      Level 2 (非阻塞LLM, 后台):
        - 语义理解：'在公司熬到12点' → 环境=公司, 活动=工作
        - 情境消歧：'在咖啡馆' vs '喝了咖啡'
        - 多轮积累：多次提到'空调太冷' → 确认环境温度问题

    推断维度：
      - sleep_environment: {'dark', 'noisy', 'cold', 'hot', 'unknown'}
      - pre_sleep_activity: {'screens', 'exercise', 'eating', 'alcohol', 'work'}
      - daily_stress_signal: {'high', 'normal', 'low'}
      - bedtime_regularity: 基于过去N天的入睡时间分布

    置信度管理：
      - level 1 推断 → 初始置信度 0.3~0.5
      - level 2 精校 → 置信度提升到 0.7~0.9
      - 时间模式积累 → 置信度逐步提升（每多一个数据点+0.05）
      - 置信度<0.3的信号不写入稳态回路
    """
```

**关键能力：**
- `infer_pre_sleep_state(message, timestamp)` → 当前是否在睡前准备状态
- `detect_circadian_slippage(chat_history)` → 从对话时间检测节律漂移
- `estimate_sleep_pressure(message_meta)` → 从消息模式估计困意程度

**v3.0 核心新增：** 把"时间"本身作为最重要的传感器。Level 1 规则引擎的核心贡献不是准确性，而是**实时性**——在LLM分析完成前先给出一个低置信度信号，让稳态回路可以立刻开始积累。

### 3.4 睡眠觉察训练 `sleep_awareness_training.py`

**这是v3.0的终极目标模块。** 前面的所有模块都是工具层面的升级，这个模块是范式的升级——从AI代理 → AI教练。

```python
class SleepAwarenessCoach:
    """
    睡眠觉察训练师

    核心目标不是"帮用户睡好"，而是"帮用户发展自己的睡眠觉察能力"。
    类比：不代写作业，而是教会怎么解题。

    训练维度：
      1. 因果觉察 — 帮助用户发现"我今天做了X → 今晚睡得Y"
      2. 体感觉察 — 教用户识别自己的困意信号（不是"我睡不着"而是"我心跳还很快"）
      3. 节律觉察 — 让用户意识到自己的生物钟模式（"原来我每到周三就晚睡"）
      4. 环境觉察 — 帮助用户识别睡眠环境中的干扰因素

    训练方法（按用户"睡眠素养"分阶段）：
      Phase 1: 引导式观察 — AI提问→用户回答→AI总结模式
      Phase 2: 自主发现 — AI减少提问，鼓励用户自己描述模式
      Phase 3: 自主管理 — 用户主动寻求AI提供的数据支持

    设计原则：
      - 不替代用户做判断（建议>指令）
      - 每次训练只需用户最小认知负担（3句以内）
      - 每两周更新用户的"睡眠素养评分"
    """
```

**Phase 1 — 引导式观察（用户初次使用~第7天）：**

```
AI: "你昨晚23:30上床，翻了好久才睡着。
     我注意到你睡前1小时在和我聊天聊工作。
     你觉得这两个事有没有关系？"
用户: "好像是，脑子停不下来"
AI: "明白了。下次可以试试睡前30分钟刻意停下工作话题，
     做2分钟深呼吸再睡。你愿意试试吗？"
```

**Phase 2 — 自主发现（第7~30天）：**

```
用户: "今晚又失眠"
AI: "我看了下这周的数据，发现你的失眠
     通常发生在工作日的周三到周四之间。
     你注意到这个模式了吗？"
用户: "还真是……"
AI: "需要我帮你回想周三晚上跟其他晚上有什么不同吗？
     还是你自己已经有点想法了？"
```

**Phase 3 — 自主管理（30天+）：**

```
用户: "帮我看看这周的模式"
AI: "可以。先说说你自己注意到了什么？"
用户: "……"
AI: "好。我补充两个数据点：你的平均入睡时长
     比上周多了12分钟，而且都是在用手机后。
     这两个一起看，对你有什么启发吗？"
```

**评价指标：**
- 睡眠素养评分（0~100）— 基于：用户主动描述模式的能力、因果推断的准确性、自主调整策略的次数
- 系统活跃度从"打开频率" → "用户自发提出假设的频率"
- 最终目标：用户不再需要AI → 系统从"陪伴"转为"数据后台"

## 6. 规则引擎 vs LLM 决策矩阵

v3.0 的设计过程中一个重要领悟：

| 场景 | 用规则引擎 | 用LLM | 理由 |
|------|-----------|-------|------|
| 数学拟合（节律相位/趋势推断） | ✅ 首选 | ❌ | 解析解更快更准，不需要语义理解 |
| 关键词匹配（"打呼"→伴侣干扰） | ✅ 初筛 | ✅ 精校 | 键词100%命中，但同义/隐含表达需要LLM |
| 语义理解（"他在隔壁打游戏太吵了"→ 伴侣干扰） | ❌ 失效 | ✅ 首选 | 规则在这里的虚假自信比不知道更危险 |
| 行为模式积累（连续3天深夜聊天→晚睡） | ✅ 首选 | ❌ | 纯统计问题，不需要理解"为什么" |
| 情感分析（"睡不着"→ 焦虑/兴奋/平静？） | ❌ 不足 | ✅ 首选 | 需要上下文判断语气和强度 |

**核心原则：能用数学/统计解决的问题不用LLM，需要语义理解的问题不用规则。两者通过异步管道分层协作。**

## 7. 不新增硬件依赖

- 所有数据来自已有输入（消息+时间+问卷），不做传感器
- 社会情境和环境线索是**被动推断**的，不是让用户填更多表
3. **范式可逆** — 如果某推断不准确，系统能明确标注"推测中"而非"自信出错"
4. **阶段性退出** — 训练模块的目标是让自己变得不需要（用户自主管理）
5. **认知科学而非经验主义** — 不做"拍脑袋的功能"，每个模块有底层理论支撑

## 8. 从"AI管理"到"认知伴侣"的本质区别

```
管理型AI (v2.x)              认知伴侣 (v3.0)
────────────                  ────────────
"你的睡眠评分是68分"          "最近3天你的入睡时间在推迟"
"建议今晚23:00前上床"        "你发现自己这个模式了吗？"
"给你推送了放松建议"          "有个数据你想看看吗？"
"请填写睡眠问卷"             "今天有什么跟睡眠有关的感受？"
成功=用户照做               成功=用户开始自己发现
```

**最根本的改变：v3.0 不满足于一个"好的睡眠"，而是培养一个"好的睡眠者"。** 即使有一天用户不再打开这个App，ta学到的东西也不会消失。
